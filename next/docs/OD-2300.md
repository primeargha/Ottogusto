# OD-2300: Parameterised category URLs — `carIds` & legacy `makeModelTypeId`

## Problem

Google is indexing category URLs with query parameters on **Ottogusto + Qverde**, across locales:

```text
/nl-NL/auto-onderdelen/categorie/motor?makeModelTypeId=00900000000000000   (legacy)
/en-BE/search-results?categoryId=001&carIds=mod8qzounygtrp                 (current)
/en-BE/car-parts?carIds=mod8qzounygtrp                                   (current)
```

| Issue                    | Summary                                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------------------------- |
| Legacy `makeModelTypeId` | Old MME brand-root IDs (`00100…`, `00500…`, etc.) — **no longer a product URL convention**                    |
| Current `carIds`         | New car search (Sprint 35+) — **intentional for user navigation**, but creates near-duplicate URLs if crawled |
| Canonical / sitemap      | Already **clean** (no query params) — Google still discovers param URLs via internal links + JSON-LD          |

**This is index bloat / split signals — not a live page outage.** Category and search-results pages work; canonicals point to clean paths.

---

## Product policy (decided)

| Param                 | Policy                                                                                                                                                                                                                |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`makeModelTypeId`** | **Retired.** Never emit in public URLs. Strip via **301** on any legacy hit. Remove remaining code that reads or writes it in hrefs.                                                                                  |
| **`carIds`**          | **Standard.** Sole vehicle-context query param when a car is selected (bookmark, hover, breadcrumb navigation). Limit Google crawling via `nofollow`, clean JSON-LD, canonical, GSC — **do not 301-strip for users**. |

> **Note (Jul 2026):** `new_mme_feature_flag` is **always on** going forward (OG + QV). The new car search flow is the only supported path — **`carIds` replaces `makeModelTypeId` entirely** in URLs. Legacy `mme_feature_flag` / `MMEBaseSearch` are not part of the product surface. Implementation may still gate on the flag in code today; new work should assume **`carIds` only** and treat `makeModelTypeId` URL handling as dead code to remove.

Env: `NEXT_PUBLIC_NEW_MME_FEATURE_FLAG` (always **true** in prod; no rollback planned).

| Area                 | Behaviour                                                                  |

## Investigation summary

### What emits parametrised URLs today

| Source                                      | `makeModelTypeId`                           | `carIds`           | Notes                                                                    |
| ------------------------------------------- | ------------------------------------------- | ------------------ | ------------------------------------------------------------------------ |
| `OGFeatureMakes`                            | Yes (when `featured_makes_feature_flag` on) | No                 | **Off** in prod — if re-enabled, must use `carIds` not `makeModelTypeId` |
| `LandingSavedcarsContainer2`                | Yes → catalog                               | No                 | **Debt** — migrate to `?carIds=`                                         |
| `BrowseByCategory2` / `CategoryL2Section`   | Legacy fallback                             | Yes (primary)      | **Remove** `makeModelTypeId` fallback branch                             |
| `MMEBaseSearch`                             | Legacy                                      | No                 | **Dead path** — `mme_feature_flag` off; do not revive                    |
| `SearchResultsBreadcrumb` + category shells | Legacy read if in URL                       | Yes                | Breadcrumb + JSON-LD — stop passing `makeModelTypeId`                    |
| `OGLanguageSelectionModel`                  | Legacy preserve                             | Preserves `carIds` | Strip `makeModelTypeId` on locale switch                                 |
| Sitemap / `generateMetadata` canonical      | No                                          | No                 | Clean paths only                                                         |

### Canonical is already clean

Category metadata (`categoryL1Metadata.ts`, `categoryL2Metadata.ts`, `categoryL3Metadata.ts`, `carPartsMetadata.ts`) sets:

```text
canonical = /{locale}/{parts-segment}/category/...   (no query string)
```

Sitemap (`app/sitemap-pages.xml/route.ts`) lists the same clean paths.

### Breadcrumb UX (current)

`OGBreadcrumb` uses real `<Link href={...}>` so browser hover shows full destination (e.g. `/en-BE/car-parts?carIds=mod8qzounygtrp`). JSON-LD `BreadcrumbList` currently uses the **same** href including params — extra crawl signal.

## Implementation plan

### Part A — Legacy `makeModelTypeId` (index cleanup)

**Goal:**

```text
/nl-NL/auto-onderdelen/categorie/motor?makeModelTypeId=00900000000000000
  → 301 →
/nl-NL/auto-onderdelen/categorie/motor
```

Apply to: **category catalog**, **L1**, **L2**, **L3** (localized parts + category segments). OG + QV.

| Step | Action                                                                                                                                                                                                                                      |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | **Middleware:** if path is category SEO page and query has `makeModelTypeId` and/or `from=brand` → **301** to same pathname without those params. Preserve unrelated query keys only if explicitly required (usually none on category SEO). |
| 2    | **Do not** `robots.txt`-disallow — keep URLs crawlable so Google processes the 301 and drops param versions.                                                                                                                                |
| 3    | **Remove emitters:** stop writing `makeModelTypeId` to any public href (saved cars carousel, `appendVehicleContextToHref` fallback, `BrowseByCategory2` / `CategoryL2Section` legacy branch, footer brand links).                           |
| 4    | **Remove readers:** category shells must not hydrate from `makeModelTypeId` in URL (301 redirect handles legacy hits; delete URL-read logic).                                                                                               |
| 5    | **Code cleanup:** remove `makeModelTypeId` branches guarded by `new_mme_feature_flag` / `mme_feature_flag` — assume new MME always; simplify to `carIds`-only paths.                                                                        |
| 6    | **GSC (ops):** configure `makeModelTypeId` as passive / no content change during transition.                                                                                                                                                |

**Do not** use **410** for these — products/categories still exist; only the param is obsolete.

---

### Part B — `carIds` (keep for users, limit crawling)

**Goal:** Users keep `<Link href="...?carIds=...">` and hover preview; Google prefers clean category URLs.

| Step | Action                                                                                                                | Where                                                                   |
| ---- | --------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 1    | Keep `<Link href="...?carIds=...">` on breadcrumbs and user nav                                                       | `components/og-components/OGBreadcrumb.tsx`                             |
| 2    | Add **`rel="nofollow"`** when `href` contains `carIds` (and legacy `makeModelTypeId` if any remain during transition) | `OGBreadcrumb.tsx`                                                      |
| 3    | **JSON-LD `BreadcrumbList`:** emit **clean** `item` URLs only (strip `carIds`, `makeModelTypeId`, `from=brand`)       | `OGBreadcrumb.tsx` — split `link.href` (user) vs `schemaHref` (crawler) |
| 4    | **Canonical** without params                                                                                          | Already done in category metadata ✓                                     |
| 5    | **GSC (ops):** configure `carIds` as passive / “doesn’t change page content”                                          | Search Console URL parameters                                           |
| 6    | **Do not** 301-strip `carIds` for normal users on search-results or category pages                                    | Unlike legacy `makeModelTypeId`                                         |

**User navigation example (unchanged after Part B):**

```text
Search results: /en-BE/search-results?categoryId=001&carIds=mod8qzounygtrp
Breadcrumb “Car parts” hover → /en-BE/car-parts?carIds=mod8qzounygtrp
```

**Google should see:**

```text
Canonical + JSON-LD + sitemap → /en-BE/car-parts
Breadcrumb <a href>        → /en-BE/car-parts?carIds=...  (rel="nofollow")
```

## Out of scope / do not do

| Action                                                  | Why                                                              |
| ------------------------------------------------------- | ---------------------------------------------------------------- |
| `robots.txt` Disallow `?carIds=` or `?makeModelTypeId=` | Blocks Google from seeing 301/canonical on legacy URLs           |
| `noindex` on pages when `carIds` present                | Would noindex real pages users browse with a car selected        |
| `router.push` instead of `<Link>` for breadcrumbs       | Loses hover URL preview in status bar                            |
| 301-strip `carIds` for users                            | Breaks car context in URL; use `nofollow` + clean schema instead |
