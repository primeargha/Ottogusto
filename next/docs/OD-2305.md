# OD-2305: Legacy `/part/` URLs — GSC 403 & phantom `-EU` locales

## Problem

Google Search Console flagged **“Blocked due to access forbidden (403)”** on ~784 URLs matching:

```text
/{locale}/part/{slug}/{partId}
```

Examples:

- `https://ottogusto.com/fr-NL/part/toyota/mfkuxwsjc4sjyr`
- `https://ottogusto.com/en-EU/part/toyota/mfk2pt4unzdohu`
- `https://ottogusto.com/fr-BE/part/REGELEENHEID/mf9amhxxfx6xn3`

**This is not a live PDP outage.** Current product detail pages live at localized parts segments (`car-parts`, `auto-onderdelen`, `pieces-auto`, `autoteile`). The same part IDs resolve correctly on those routes.

| Issue                 | Summary                                                                 |
| --------------------- | ----------------------------------------------------------------------- |
| Legacy `/part/` URLs  | Old route removed Oct 2025; Google still re-crawls indexed URLs         |
| Phantom `-EU` locales | `en-EU`, `nl-EU`, `fr-EU` are not configured markets                    |
| GSC 403               | Not reproduced from Next.js today; likely infra/WAF or stale crawl data |
| Soft 404              | Legacy URLs often return **HTTP 200** with “Page not found” body        |

## Investigation summary

### Current PDP routing

| Aspect                 | State                                                                    |
| ---------------------- | ------------------------------------------------------------------------ |
| App route              | `app/(public)/[language-country]/car-parts/[partname]/[partid]/page.tsx` |
| Public URL             | `/{locale}/{parts-segment}/{manufacturer-or-seo-slug}/{partId}`          |
| URL builder            | `utils/build-part-pdp-url.ts` → `buildPartPdpHref()`                     |
| Literal `/part/` route | **Does not exist**                                                       |

### Legacy `/part/` timeline

| Date               | Change                                             |
| ------------------ | -------------------------------------------------- |
| Apr 2025           | First PDP: `/{lang}/part/{partId}`                 |
| Jun 2025 (OD-832)  | Shape becomes `/{locale}/part/{partname}/{partId}` |
| Oct 2025 (OD-1226) | Route moved to `car-parts/` filesystem tree        |
| May 2026 (OD-2107) | Unified localized segments via middleware rewrites |

Old PDP metadata emitted `/part/` in OpenGraph and JSON-LD:

```text
/${languagecountry}/part/${product?.name || "part"}/${partid}
```

That explains:

- Why Google still has `/part/` indexed
- Why segment 2 varies (`toyota` vs `REGELEENHEID` vs `VELG`) — old code used `product.name`, not manufacturer slug

### What does **not** emit `/part/` or `-EU` today

| Source                                                                | `/part/`? | `-EU`? |
| --------------------------------------------------------------------- | --------- | ------ |
| `buildPartPdpHref()`                                                  | No        | No     |
| `utils/hreflang.ts`                                                   | No        | No     |
| `app/sitemap-pages.xml/route.ts`                                      | No        | No     |
| CDN product sitemaps (`static.ottogusto.com/ottogusto/sitemap-*.xml`) | No        | No     |

Configured URL locales (`config/lang-country-combinations-env.ts`): **BE, NL, FR, LU only** — no `*-EU`.

### Live behaviour (Jul 2026)

| URL type                             | HTTP | Body                        |
| ------------------------------------ | ---- | --------------------------- |
| `/{locale}/part/...` (legacy)        | 200  | “Page not found” (soft 404) |
| `/{locale}/car-parts/...` (live PDP) | 200  | Full product page           |

Middleware `parsePdpCandidate()` only matches known parts segments (`car-parts`, `auto-onderdelen`, etc.). The literal segment `part` is ignored — no redirect or canonicalization runs.

## Proposed solution

### 1. Legacy `/part/` → canonical PDP (301)

Add middleware handling for paths matching:

```text
/{locale}/part/{slug}/{partId}
```

**Algorithm** (extend existing malformed-PDP logic in `middleware.ts`):

1. Detect `/part/` as a legacy PDP candidate (separate from `parsePdpCandidate`, which only knows current segments).
2. Validate `partId` with `isValidPartIdForApi()`.
3. `GET /parts/{partId}` to resolve manufacturer slug and confirm product exists.
4. If product exists → **301** to:

   ```text
   /{locale}/{correct-parts-segment}/{manufacturerSlug}/{partId}
   ```

   - Use `getPartsRouteSegmentForLang()` for the segment.
   - If locale is invalid (e.g. `en-EU`), map to a sensible default (`en-BE`) or use locale from allowlist when partial match exists.
   - Preserve query string (`makeModelTypeId`, `carIds`) via existing `handleQueryStringPreservation`.

5. If product API returns 404 → **410 Gone** (see below).

Reuse patterns already in `middleware.ts` PDP wrong-URL handling (lines ~298–393).

### 2. Permanently removed products → 410 Gone

When `GET /parts/{partId}` returns 404 for a legacy `/part/` URL:

- Return **410 Gone** (not 404, not 200 soft-404).
- Tells Google the URL is deliberately dead and should drop from the index.

**410 vs 404:**

| Code    | Use when                                                          |
| ------- | ----------------------------------------------------------------- |
| **301** | Product still exists on `car-parts` route                         |
| **410** | Product deleted; no replacement URL                               |
| **404** | Avoid for known-legacy URL patterns — less clear signal to Google |

### 3. Phantom `-EU` locales

No sitemap/hreflang changes needed — current code is already clean.

For requests like `/en-EU/part/...`:

- **301** to canonical PDP on a real locale (e.g. `en-BE`) when part exists
- **410** when part does not exist
- Do **not** add `*-EU` to `LANG_COUNTRY_COMBINATIONS`

Optional cleanup (low priority): audit `localStorage.locale === "en-EU"` from `newApiClient.ts` default — internal API only, does not emit crawlable URLs.

### 4. Fix soft 404s

Today, unknown `/part/` paths return **HTTP 200** with not-found UI. After middleware handling:

- Legacy `/part/{slug}/{id}` with valid part id → 301 or 410 (never 200)
- Any remaining unmatched `/part/` paths → true **404** via `notFound()`, not `<NotFound />` component with 200

Align with existing PDP page behaviour goal: real HTTP status matches page semantics.

### 5. GSC 403 — infra check (parallel track)

Next.js does not return 403 for `/part/` paths. Before or after deploy:

1. **GSC URL Inspection** on 2–3 example URLs — confirm current status vs 24 Jun crawl.
2. **Azure Front Door / App Service logs** — filter `status=403` + Googlebot UA for `/part/` paths (~15 Jun–01 Jul 2026).
3. On Qverde: non-allowlisted locales (e.g. `en-EU`) hit `/Proxy{pathname}` in middleware — verify Proxy API never returned 403 historically.

If 403 was transient infra, redirects/410s still fix the underlying index pollution.

### 6. Do **not** robots-disallow `/part/`

Keep legacy URLs **crawlable** so Google can follow 301/410 and process removals. Do not add `/part/` to `ROBOTS_DISALLOW`.
